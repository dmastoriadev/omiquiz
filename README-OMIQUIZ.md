# Omiquiz avatar hosting fix

Merge the app and routes folders into your existing Omiquiz project, replacing the two matching PHP files. Apply the same files to your local repository so the next deployment retains the fix.

## Live server

After uploading the files, run via SSH:

```bash
cd ~/htdocs/omi.ahrgrpwebdrafts.com
php artisan optimize:clear
```

Refresh player, spectator and host pages with Ctrl+F5. No migration, npm build, storage link or new avatar image upload is needed.

## What changed

The avatars are generated by Laravel. Their old URLs ended in .svg, which can match CloudPanel/Nginx static-file rules before the request reaches Laravel. The new canonical URLs use:

- /avatars/rpg/1/portrait
- /avatars/rpg/1/sprite

Both still return SVG artwork with the correct image/svg+xml content type. Relative URLs inherit the current page's domain and HTTPS connection. Existing .svg routes remain available when the server forwards them to Laravel. Existing player identities and artwork are unchanged.

## Verify on your live site

Open https://omi.ahrgrpwebdrafts.com/avatars/rpg/1/portrait and https://omi.ahrgrpwebdrafts.com/avatars/rpg/1/sprite. Both should show a character. If either still fails, capture that request's HTTP status in the browser Network tab; a 404, 403 and 500 require different follow-up checks.

## Validation

75 focused HTTP checks passed with cached Laravel routes, covering extensionless URLs, valid SVG, correct MIME headers, no session cookies, supported legacy URLs, invalid-ID rejection and relative URLs under HTTP/HTTPS. Both changed PHP files passed syntax checks.

The live server could not be inspected, so static-rule interception is a source-backed likely cause, not a confirmed live-server diagnosis.
